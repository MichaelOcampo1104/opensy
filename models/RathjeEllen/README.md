# RathjeEllen

**Purpose:** 2D coupled u-p effective-stress site response analysis of a layered
soil profile (loose-sand crust over dense-sand base) using PM4Sand
liquefaction constitutive models and a Lysmer dashpot base — parametric in
liquefiable-layer thickness and crust thickness (18-case sweep).

**Building System:** 2D soil profile extending from the ground surface down to
an elastic half-space. Loose-sand liquefiable layer of variable thickness
(2–20 m) overlies a dense-sand base; the surface crust thickness (2, 4, 6, 8 m)
is also varied. Free-field columns flank the central mesh at large distance.
PM4Sand materials model both the loose (Dr = 0.55) and dense (Dr = 0.85) sands.

**Model Description:** 2D finite-element model with 4-node SSPquadUP coupled
u-p elements (single-point stabilization, Biot porous-solid-fluid). Four PM4Sand
materials (loose/dense × main/free-field column) plus a Viscous Lysmer dashpot
at the base. Three-phase analysis: (1) elastic gravity consolidation
(10 steps, dt = 500 s), (2) plastic gravity consolidation with `FirstCall`
initialisation (10 steps, dt = 1 s), (3) transient dynamic analysis driven by
a base velocity time history applied as a force = velocity × dashpot coefficient
(3301 pts at dt ≈ 0.005 s, analysis dt = 0.001 s). Rayleigh damping 2% on
0.2–20 Hz. OpenSeesPy `ProfileSPD` solver (Tcl source used Mumps, unavailable
in openseespy) and `opst.anlys.SmartAnalyze` for the dynamic loop
(replacing the Tcl's hand-rolled substepping).

The mesh is **auto-generated by GiD** (`UWquad2D` problem type, McGann &
Arduino, U. Washington) and is irregular — the Python model reads it from
per-case `.dat` files rather than re-deriving it. The 18 cases differ only in
mesh geometry; materials, ground motion, and analysis logic are identical.

| Field | Value |
|-------|-------|
| Dimensions | 2D |
| Material | PM4Sand (loose + dense, with free-field duplicates) |
| Lateral System | Soil profile with free-field columns + base Lysmer dashpot |
| Lateral Loading | Dynamic base excitation (velocity input via dashpot) |
| Earthquake Records | motion1.{vel,time,acc} — 3301 pts @ dt ≈ 0.005 s (shared across all cases) |
| Design Year | NA |
| File Format | .py |
| OpenSees Version | Standard OpenSeesPy |
| Units | kN, m, kPa, sec (coupled u-p — retained per AGENT.md §3a/§12j and pedroArduino_freefield precedent) |

**Running a case:**

```bash
conda activate opensy
python model.py 2_HA_2_H        # default case
python model.py 12_HA_8_H       # any of the 18 cases in cases/
```

Outputs land in `output/<case>/`. Available cases are listed in `cases/`.

**Notes:**
Converted from `tcl_ref/loose/*/final_model.tcl` (18 cases). The mesh data
files (`nodeInfo.dat`, `elementInfo.dat`, `nodeFixitiesInfo.dat`,
`nodeEqualDOFInfo.dat`, `firstCall.dat`) are GiD-generated and case-specific;
the ground motion (`motion1.{time,vel,acc}`) is shared across all cases. Units
are retained as kN-m-kPa-sec — converting PM4Sand empirical constants and
fluid bulk/permeability to N-mm would destroy numerical conditioning (see the
same decision in `pedroArduino_freefield`, `misty_effective stress site resp`,
and AGENT.md §12j). Two openseespy substitutions: Mumps → ProfileSPD (Mumps
unavailable), and the Tcl's manual `subStepAnalyze` → `opst.anlys.SmartAnalyze`
(subsumes the same convergence-management logic). The `medium` and
`very_loose` soil-set variants exist in `tcl_ref/` but are not yet converted
— they share the same mesh/analysis and differ only in the loose-sand PM4Sand
`Dr`/`G0`/`kDr`/`mDr` constants.
