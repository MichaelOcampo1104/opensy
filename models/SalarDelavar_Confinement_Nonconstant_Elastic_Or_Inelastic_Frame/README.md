# SalarDelavar_Confinement_Nonconstant_Elastic_Or_Inelastic_Frame

**Purpose:** Comparison of the elastic and the inelastic behaviour of a 2D reinforced-concrete frame with fibre sections whose confinement enhancement ratio varies along the frame: a monotonic pushover to 675 mm (bilinear fit, over-strength factor, ductility, R and the damage index) and a time-history run under the X record, with the source's Rayleigh damping. First sub-model of the source folder `CONCRETE_FRAME_EXAMPLES/CONFINEMENT_ENHANCEMENT_RATIO`, which holds seven sub-models.

**Building System:** A single-storey, single-bay portal frame with both bases fixed. The columns are 3 m high and 500 x 500 mm, with 50 mm cover and six 25 mm bars (three on each face in the plane of the frame). The beam spans 7 m between the column axes and is 500 mm wide and 300 mm deep, with 50 mm cover and eight 18 mm bars (three top, two middle, three bottom). The confinement enhancement ratio is 1.25 for elements 1, 3, 4 and 6, 1.10 for elements 2 and 5, 1.15 for elements 7 and 9 and 1.05 for element 8, as in the source.

**Model Description:** 2D model with three DOFs per node (ndm = 2, ndf = 3) and ten nodes. Nine corotational beam-column elements. The inelastic run uses `nonlinearBeamColumn` with 10 integration points; the elastic run uses `elasticBeamColumn` on the same fibre sections (Note 3). Each section has its own materials, as in the source: Concrete01 for the core (strength 25 MPa times the ratio) and for the cover (25 MPa), and Hysteretic reinforcement (f_y = 4000 MPa, E_s = 2 x 10^5 MPa). The fibres form 40 x 5 patches. Analyses, each run for both element kinds:
1. Pushover: horizontal displacement control of node 4 (DOF 1) from 0 to 675 mm in 0.05 mm steps (13,500 steps) with SmartAnalyze (NormDispIncr, tolerance 1 x 10^-6, 5000 iterations, algorithm ladder 10, 41, 40, 20, 50, 60). The reference load is 1 N horizontal and -1 N vertical at nodes 3 and 4, and the load factor is the output. Recorded at each step: load factor, node-3 displacements and rotation, base reactions (sum over both bases) and the stiffness ratios KS, KA and KI.
2. Time history: the X record scaled by GMfact (9810 mm/s^2) and by SSF_X = 10, Newmark (0.5, 0.25), dt = 0.01 s, 50 s (5000 steps) with SmartAnalyze (ladder 10, 41, 40, 20, 50). Modal Rayleigh damping from the first two modes (5 % and 3 %) through the source's helper. Recorded at each step: displacements and velocity and acceleration of node 3, base reactions, the stiffness ratios and the shortest and longest of the first four periods.

**Validation:** `output/validation.txt`, from the final run of this folder:
- **Element assembly.** The force-based element with gross sections reproduces the textbook frame element to 1.7 x 10^-15.
- **Section properties (gross, initial tangents).** Column EA = 5.851 x 10^9 N and EI = 1.427 x 10^14 N.mm^2; beam EA = 3.576 x 10^9 N and EI = 2.996 x 10^13 N.mm^2.
- **First pushover step, elastic run.** OpenSees 1068.832 and numpy 1068.849 (relative difference 1.6 x 10^-5).
- **First pushover step, inelastic run.** OpenSees 299.8451 and numpy 299.8672 (7.4 x 10^-5), with the section states of the first step and 10 Lobatto points. The node-3 displacement is 0.04502298 mm (OpenSees) and 0.04502249 mm (numpy).
- **Equilibrium** over all 13,500 steps. Elastic: 9.1 x 10^-15 (horizontal) and 8.8 x 10^-14 (vertical). Inelastic: 3.8 x 10^-12 and 1.9 x 10^-11.
- **Periods and Rayleigh coefficients.** The four lowest periods of the frame with the lumped mass (LESSON 69) are 7.584309, 2.440709, 1.832704 and 1.030376 s, which match OpenSees to six digits. The numpy coefficients alpha_M = 7.457112 x 10^-2 1/s and beta_K = 1.205471 x 10^-2 s match the OpenSees values, and they give modal ratios of 5.0000 % and 3.0000 % for modes 1 and 2.
- **Elastic time history against a linear Newmark replica** (the excitation of OpenSees, LESSON 70). Node-3 displacement: 1.3 x 10^-8 over the first 5 steps, while |u| <= 1 mm; 2.1 x 10^-4 over 43 steps (0.43 s), while |u| <= 10 mm; 2.5 x 10^-2 over the whole record. The last figure comes from the corotational transformation of the run (Note 1; LESSON 72).
- **Base shear of the time history:** not validated (Note 16).
- **Not validated:** the inelastic time history, beyond its first periods. The bilinear fit, the over-strength factor, the ductility and R are the source's formulas, ported, and are reported rather than checked against an independent solution.

**Notes:**
1. **Corotational transformation.** Both runs use the source's corotational transformation, so the elastic run is linear in its materials only. Its geometric nonlinearity departs from a linear replica after the first few tenths of a second (Validation). The elastic peak displacement is 328.7 mm, against 325.5 mm for the same model with a linear transformation (scratch check, Note 17).
2. **Cracked from the first step.** Concrete01 has no tensile strength, so the inelastic frame is cracked from the first pushover step: its first load factor is 299.8, against 1068.8 for the gross elastic frame (ratio 0.28). The gross section is not a reference for the inelastic run (LESSON 65 for the composite section model).
3. **Elastic branch.** The source's ELASTIC branch calls `elasticBeamColumn` with the fibre section tag. OpenSeesPy 3.8 accepts this and gives the element the linear stiffness of that section (gross, initial tangents). A scratch probe with the source's concrete and steel stayed linear to 0.03 % at a tip displacement of 63 mm, whereas the nonlinear element was 3.5 times as flexible at 10^4 N. The elastic first step agrees with the gross numpy frame to 1.6 x 10^-5.
4. **Confinement ratios.** Kc = 1.25 (elements 1, 3, 4 and 6), Kc - 0.15 = 1.10 (2 and 5), Kc - 0.10 = 1.15 (7 and 9) and Kc - 0.20 = 1.05 (8). The source's section formulas are kept: the core peak stress is the ratio times 25 MPa, the strain at the peak is 1.8 times that of the cover, and the ultimate values follow the source.
5. **Masses.** The source labels its nodal mass `MASS = 12000` as [kg] and takes its element masses from the factors `Bc*Hc*0.000025 = 6.25` and `Bb*Hb*0.000025 = 3.75`. OpenSees uses the N-mm-s system here (the record in mm/s^2), so every value is read as N.s^2/mm (per unit length: N.s^2/mm^2). As written, the total mass is 87,750 N.s^2/mm (87,750 t). The periods are then 7.58, 2.44, 1.83 and 1.03 s. Read as kg, every mass is 1000 times smaller and the periods are 0.0316 times these: 0.240, 0.077, 0.058 and 0.033 s, so the shortest period spans only 3.3 steps of dt = 0.01 s. As a density, the element mass of 6.25 N.s^2/mm^2 is about 10^4 times the mass of a 500 x 500 mm concrete column at 2500 kg/m^3 (about 0.6 t/m); read as kg/m it is about 100 times lighter. The values are kept as written, and the choice is left to the author (LESSON 71).
6. **Ramp load in the time history.** The source adds 1 N horizontal load at nodes 3 and 4 in the same `Linear` pattern used for the pushover. A Linear time series grows with time in a transient analysis, so this load is t N (50 N at 50 s). A scratch probe confirmed the proportionality. Kept as written; it is small against the seismic inertia (LESSON 73).
7. **Rayleigh damping.** The source's helper computes alpha_M and beta_K from the first two modes, with 5 % for mode 1 and 3 % for mode 2 (the call uses `DR` and `0.6*DR`). It passes beta_K as the fourth argument of `ops.rayleigh`, which is the committed-stiffness coefficient, although its comments describe a current-stiffness coefficient. Kept as written. The difference matters only for the inelastic run, where the stiffness term acts on the last converged stiffness.
8. **Ground excitation.** OpenSees applies the X record to the free DOFs with the full element mass m L at each free end of every element, plus the nodal masses once. The eigenvalues and the effective mass of the transient use the lumped mass m L/2 per end (LESSON 69). The replica applies the excitation this way (LESSON 70). With the textbook force M r, the replica differs from OpenSees by 41 % over 1000 steps.
9. **Stress-strain recorders.** The source's recorders (`STRESS_STRAIN_FUN.py`) are replaced by element queries (`ops.eleResponse`) of the same fibres at every step of the inelastic time history. The source names the concrete point at y = +H/2 "BOT", because its recorder negates the coordinate it is given. The names are kept, so `CONCRETE_BOT` is the fibre at +H/2. The rebar points are named as in the source.
10. **Logarithmic decrement.** The source's `DAMPING_RATIO` function returns 0 when any local maximum of the displacement is not positive. Both time-history runs return 0 %. The record is forced, so the value is not a modal damping ratio (LESSON 62). The modal ratios of the coefficients are in Validation.
11. **Node 3 and node 4.** The pushover controls node 4 (DOF 1) to 675 mm, and the source records node 3. At the end of the inelastic pushover, the node-3 displacement is 683.6 mm, which is larger than the control. The bilinear fit, the ductility and R use the node-3 displacement, as the source does.
12. **Bilinear fit and damage index.** The equal-area fit of the inelastic pushover (slope node 10, as the source) gives Omega_0 = 1.1615 and mu = 5.7515, so R = 6.6802. The damage index is 0.5790 in X, from the peak node-3 displacement of the inelastic time history (445.9 mm). The axial fit gives Omega_0 = 0.9264, a value below 1 that the source's formula returns as written, and a damage index of 0.2634 in Y.
13. **Solver.** Both pushovers completed all 13,500 steps to the 675 mm control. Both time histories completed all 5000 steps with SmartAnalyze, and no step failed.
14. **Output files.** The source's Excel export (30 columns for the two cases) is written as CSV: `dynamic_elastic.csv` and `dynamic_inelastic.csv`, each with a TIME column.
15. **Not converted.** The Y record and the `SEI = 'Y'` and `'XY'` branches, so `SSF_Y` is not used. The fallback ladder of `ANALYSIS_FUNCTION.py` is replaced by SmartAnalyze. The printed text is replaced by the result files, and the matplotlib windows by PNG files. `PLOT_2D.py` (not run) and `SALAR_MATH.py` (not used by the source's main) are kept as copies only.
16. **Base shear of the time history.** The replica does not reproduce the base shear: the OpenSees reaction includes the element inertia and damping forces at the bases, and their convention was not isolated here. The base shear is therefore not validated.
17. **Scratch checks (not in this folder).** These were run from a scratch folder and are cited for transparency: a cantilever element gave the lumped eigenvalues 96 and 320 (LESSON 69); a single mass on a spring matched the textbook Newmark step exactly; the frame's excitation rule (Note 8) reproduces the first four displacements to seven digits; and the replica agrees with a run of the same model with a linear transformation to 3.6 x 10^-11 over all 5000 steps.
18. **Run time.** The elastic pushover takes 5 s and the inelastic pushover 3 min 28 s (13,500 steps each). The elastic time history takes 7 s and the inelastic one 1 min 16 s (5000 steps each). The whole script takes about five minutes on this machine. The console must use UTF-8: the progress bar prints a rocket emoji, which stops a cp1252 console with redirected output (LESSON 35).

**Outputs** (in `output/`, git-ignored): `pushover_elastic.csv` and `pushover_inelastic.csv` (13,500 steps, with the source's column names), `dynamic_elastic.csv` and `dynamic_inelastic.csv` (5000 steps, with TIME), `stress_strain_inelastic_dynamic.csv` (5000 steps, 48 columns), `pushover_results.txt`, `dynamic_results.txt`, `validation.txt`, `model_info.json` (the OpenSees model of the last analysis), the figures `pushover_curve.png`, `dynamic_response.png` and `stress_strain.png`, the views `vis_01_nodes.html` to `vis_04_pre_analysis.html`, `vis_05_deformed_inelastic_pushover.html`, `vis_08_pushover.html` and `vis_09_dynamic.html`, and the ODBs `RespStepData-*.odb` with their `ModelData-*.zarr` folders for the four analyses.
